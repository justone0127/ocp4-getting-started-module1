== OpenShift란 무엇인가요?

link:https://www.redhat.com/en/technologies/cloud-computing/openshift[OpenShift^]는 개발팀이 온프레미스, 퍼블릭 클라우드, 하이브리드 환경 등 모든 인프라에서 애플리케이션을 배포하고 관리하며 스케일링할 수 있도록 지원하는 컨테이너 기반 애플리케이션 플랫폼입니다.

== 컨테이너란 무엇인가요?

link:https://www.redhat.com/en/topics/containers/whats-a-linux-container-vb[컨테이너^]는 애플리케이션과 그에 필요한 모든 종속성을 함께 패키징하는 표준화된 방식입니다. 이 방식은 배포를 단순화하고 제공 속도를 높여줍니다. 가상 머신과 달리 컨테이너는 전체 운영체제를 포함하지 않습니다. 컨테이너 안에는 애플리케이션, 런타임, 라이브러리, 설정만 패키징됩니다. 이 덕분에 컨테이너는 가상 머신에 비해 더 가볍고 이식성이 뛰어나며 효율적인 배포 모델이 됩니다.

이러한 컨테이너 기반 위에서, link:https://openshift.com/[OpenShift^]는 워크플로우를 간소화하고 검증된 통합 기능을 제공하는 완전한 플랫폼을 통해 효율적인 애플리케이션 개발을 지원합니다. 이는 프로젝트를 신속하게 진행하려는 개발팀과 표준화된 애플리케이션 플랫폼을 찾는 조직에게 이상적입니다.

== 이 워크샵의 OpenShift 환경

지금까지 OpenShift와 컨테이너가 무엇인지 살펴봤으니, 이제 실습에 사용할 실제 환경을 소개합니다.

image::common-environment-ocp-architecture.png[OpenShift Architecture,link=self,window=blank]

이 워크샵은 Red Hat이 퍼블릭 클라우드에서 운영하는 **Red Hat Developer Sandbox** 환경에서 진행합니다. Sandbox는 여러 사용자가 하나의 OpenShift 클러스터를 함께 사용하되, 사용자마다 격리된 Project(namespace)를 하나씩 제공하는 공유 환경입니다. 이 클러스터는 다음과 같은 시스템으로 구성됩니다:

* Control Plane 노드
* Worker 노드(또는 "애플리케이션" 노드)
* 동적 프로비저닝 스토리지
* 내부 컨테이너 레지스트리
* 라우팅 레이어

여러분은 클러스터 관리자가 아니라 **자신의 Project 안에서 일하는 개발자**의 입장에서 실습합니다. 그래서 노드 설정처럼 클러스터 전체에 영향을 주는 작업은 직접 해보지 않고, 개념과 동작 결과를 확인하는 방식으로 다룹니다.

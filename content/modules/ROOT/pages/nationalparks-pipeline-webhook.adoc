= 파이프라인과 Webhook
:navtitle: 파이프라인과 Webhook

include::vars.adoc[]

OpenShift에 내장된 구성 요소 외에도, OpenShift Pipelines는 link:https://tekton.dev/docs/triggers/[**Tekton Triggers**^] 덕분에 파이프라인에 추가적인 트리거와 자동화 기능을 제공합니다.

NOTE: 이 보너스 실습에서는 여러분의 **GitHub 계정**으로 예제 저장소를 fork해서 사용합니다. GitHub 계정이 없다면 먼저 link:{ocp4_starter_github_url}[GitHub^]에서 가입해 주세요.

[#trigger_setup_group]
== 트리거 구성

[#webhooks]
=== 배경 지식: Web Hook

대부분의 Git 저장소 서버는 Web Hook이라는 개념을 지원합니다. 코드 저장소에
변경이 발생하면 HTTP(S)를 통해 외부 소스를 호출하는 것입니다.
OpenShift는 빌드를 트리거하기 위해 원격 시스템으로부터 Web Hook을 수신할 수 있는 API
엔드포인트를 제공합니다. 이 Web Hook을 바로 다음 섹션에서 만들 TriggerTemplate/TriggerBinding/EventListener와
연결하면, 자동화된 코드/빌드/배포 파이프라인을 구현할 수 있습니다.

[#adding_triggers_to_your_pipeline]
=== 실습: 파이프라인에 트리거 추가하기

Tekton **Trigger**를 사용하면 Web Hook 같은 외부 이벤트(Git push 이벤트, pull request 등)에 반응하도록 Pipeline을 구성할 수 있습니다.

트리거 지원을 추가하려면 project에 ``TriggerTemplate``, ``TriggerBinding``, ``EventListener``를 생성해야 합니다.

[.bordershadow]
image::devops-pipeline-triggers.png[TriggerTemplate/TriggerBinding/EventListener 트리거 구성 요소 다이어그램,link=self,window=blank]

각 구성 요소를 자세히 살펴보겠습니다:

* **TriggerTemplate**: 새로 생성할 리소스에 대한 템플릿입니다. 파라미터를 받아 ``PipelineRun``을 생성합니다.
* **TriggerBinding**: 이벤트를 검증하고 페이로드 필드를 추출합니다
* **EventListener**: ``TriggerBinding``과 ``TriggerTemplate``을 연결하여 주소 지정이 가능한 엔드포인트(이벤트 싱크)로 만듭니다. 각 TriggerBinding에서 추출된 이벤트 파라미터(및 제공된 정적 파라미터가 있다면 그것도 함께)를 사용하여 해당 TriggerTemplate에 지정된 리소스를 생성합니다. 또한 선택적으로 interceptor 필드를 통해 외부 서비스가 이벤트 페이로드를 사전 처리하도록 할 수도 있습니다.

이제 Pipeline을 위해 이들을 한 번에 생성해 보겠습니다. 웹 콘솔 오른쪽 상단의 **+** (Import YAML) 아이콘을 클릭하고, 다음 YAML을 붙여넣은 뒤 **Create**를 클릭합니다:

[source,yaml,role="copypaste"]
----
apiVersion: triggers.tekton.dev/v1beta1
kind: TriggerTemplate
metadata:
  name: nationalparks
spec:
  params:
    - name: git-revision
    - name: git-repo-url
  resourcetemplates:
    - apiVersion: tekton.dev/v1
      kind: PipelineRun
      metadata:
        generateName: nationalparks-deploy-
        labels:
          tekton.dev/pipeline: nationalparks-pipeline
      spec:
        params:
          - name: APP_NAME
            value: nationalparks
          - name: APP_GIT_URL
            value: $(tt.params.git-repo-url)
          - name: APP_GIT_REVISION
            value: $(tt.params.git-revision)
        pipelineRef:
          name: nationalparks-pipeline
        workspaces:
          - name: app-source
            persistentVolumeClaim:
              claimName: app-source-pvc
          - name: maven-settings
            emptyDir: {}
---
apiVersion: triggers.tekton.dev/v1beta1
kind: TriggerBinding
metadata:
  name: nationalparks
spec:
  params:
    - name: git-repo-url
      value: $(body.repository.clone_url)
    - name: git-revision
      value: $(body.after)
---
apiVersion: triggers.tekton.dev/v1beta1
kind: EventListener
metadata:
  name: nationalparks
spec:
  serviceAccountName: pipeline
  triggers:
    - bindings:
        - ref: nationalparks
      template:
        ref: nationalparks
---
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  labels:
    app.kubernetes.io/managed-by: EventListener
    app.kubernetes.io/part-of: Triggers
    eventlistener: nationalparks
  name: el-nationalparks
spec:
  port:
    targetPort: http-listener
  tls:
    termination: edge
  to:
    kind: Service
    name: el-nationalparks
    weight: 100
----

NOTE: ``TriggerBinding``은 GitHub push 이벤트의 페이로드에서 저장소 주소(``repository.clone_url``)와 커밋 ID(``after``)를 꺼내 파이프라인 파라미터로 넘겨줍니다. 그래서 Webhook을 통해 실행되면 원본 저장소가 아니라 **여러분이 fork한 저장소**의 최신 커밋으로 빌드됩니다.

이렇게 하면 GitHub에 Web Hook을 설정하여 Pipeline의 자동 시작을 트리거하는 데 사용할 수 있는 Route가 있는 새 Pod가 생성됩니다.

**Topology** 화면에서 ``EventListener``를 위한 새 Deployment **el-nationalparks**가 생성되었는지 확인합니다.
(아이콘 이미지는 스크린샷과 다를 수도 있습니다.)

[.bordershadow]
image::devops-pipeline-triggers-eventlistener.png[Topology 화면의 el-nationalparks EventListener Deployment,width=500,link=self,window=blank]

웹 터미널에서도 확인할 수 있습니다:

[source,bash,role="copypaste"]
----
oc get eventlistener nationalparks
----

``AVAILABLE`` 열이 ``True``가 되면 이벤트를 받을 준비가 된 것입니다.

[#webhook_integration_group]
== GitHub Webhook 연동

[#fork_repository]
=== 실습: nationalparks 저장소 fork하기

Webhook을 설정하려면 저장소의 설정을 바꿀 수 있어야 하므로, 원본 저장소를 여러분의 GitHub 계정으로 fork합니다.

. GitHub에 로그인한 상태에서 link:{ocp4_starter_nationalparks_repo}[nationalparks 원본 저장소^]로 이동합니다.
. 화면 오른쪽 위의 **Fork** 버튼을 클릭합니다.
. **Owner**에서 여러분의 계정을 선택하고, **Repository name**은 ``nationalparks`` 그대로 둡니다.
. **Copy the ``master`` branch only**가 체크된 상태로 **Create fork**를 클릭합니다.

잠시 후 ``https://github.com/<GitHub-사용자명>/nationalparks`` 주소로 여러분의 저장소가 만들어집니다.

[#configuring_webhooks]
=== 실습: GitHub Web Hook 구성하기

이 섹션에서는 fork한 ``nationalparks`` 저장소에 변경이 있을 때마다 파이프라인 실행을 트리거하는 Web Hook을 설정합니다.

먼저 ``EventListener``가 노출한 Route 주소를 확인합니다. 이 주소가 Web Hook의 URL이 됩니다:

[source,bash,role="copypaste"]
----
echo https://$(oc get route el-nationalparks -o jsonpath='{.spec.host}')
----

[.console-output]
[source,subs="attributes"]
----
https://el-nationalparks-{ocp4_starter_project}.{ocp4_starter_apps_domain}
----

출력된 주소를 복사해 둡니다. 이제 GitHub에서 fork한 저장소로 이동합니다.

. 저장소 화면 위쪽의 **Settings** 탭을 클릭합니다.
. 왼쪽 메뉴에서 **Webhooks**를 클릭한 후 **Add webhook** 버튼을 클릭합니다. GitHub 비밀번호 확인을 요구하면 입력합니다.
. **Payload URL**에 앞서 복사한 EventListener 주소를 붙여넣습니다.
. **Content type**을 ``application/json``으로 변경합니다.
. **Which events would you like to trigger this webhook?** 에서 **Just the push event**가 선택되어 있는지 확인합니다.
. **Add webhook**을 클릭합니다.

Webhook 목록에서 방금 추가한 항목 옆에 초록색 체크 표시가 나타나면, GitHub가 EventListener에 테스트 이벤트(ping)를 성공적으로 보낸 것입니다.

NOTE: GitHub의 Webhook 설정 화면은 스크린샷(Gitea 화면)과 모양이 다르지만, 입력하는 항목(Payload URL, Content type)은 같습니다.

[.bordershadow]
image::nationalparks-codechanges-config-webhook.png[Payload URL과 Content Type을 설정하는 Webhook 구성 화면,link=self,window=blank]

짜잔! 이제부터는 fork한 GitHub 저장소에 새로운 소스 코드를 커밋할 때마다
OpenShift에서 새로운 빌드와 배포가 발생합니다. 직접 시도해
보겠습니다.

[#using_webhooks]
=== 실습: GitHub Web Hook 사용하기

다음으로, GitHub 웹 화면에서 파일을 수정하고 변경 사항을 커밋해 보겠습니다.

fork한 저장소에서 ``src/main/java/com/openshift/evg/roadshow/parks/rest``로 이동하여 ``BackendController.java`` 파일을 엽니다.

파일 화면 오른쪽 위의 연필 모양(**Edit this file**) 아이콘을 클릭합니다.

20번째 줄을 다음과 같이 변경합니다. (National Parks -> Amazing National Parks)

[source,java,role="copypaste"]
----
return new Backend("nationalparks","Amazing National Parks", new Coordinates("47.039304", "14.505178"), 4);
----

화면 오른쪽 위의 **Commit changes...** 를 클릭하고, 커밋 메시지를 자유롭게 입력한 뒤 **Commit directly to the ``master`` branch**가 선택된 상태로 **Commit changes**를 클릭합니다.

변경 사항을 커밋하면 GitHub가 EventListener로 push 이벤트를 보내고, 새로운 **PipelineRun**이 자동으로 트리거됩니다.

웹 콘솔의 **Pipelines → Pipelines**에서 ``nationalparks-pipeline``을 클릭한 후 **PipelineRuns** 탭을 확인하거나, 다음 명령을 실행하여 확인합니다:

[source,bash,role="copypaste"]
----
oc get pipelineruns
----

새 PipelineRun이 실행 중인 것을 확인할 수 있습니다:

[.console-output]
[source]
----
NAME                           SUCCEEDED   REASON      STARTTIME   COMPLETIONTIME
nationalparks-deploy-x7k2p     Unknown     Running     30s
nationalparks-pipeline-abc12   True        Succeeded   20m         15m
----

파이프라인이 완료되면(``SUCCEEDED``가 ``True``), 새 이미지가 자동으로 배포되었는지 확인합니다:

[source,bash,role="copypaste"]
----
curl -s https://$(oc get route nationalparks -o jsonpath='{.spec.host}')/ws/info/
----

반환된 JSON 문자열에서 ``displayName``이 방금 설정한 새 이름(``Amazing National Parks``)으로 변경된 것을 확인할 수 있을 것입니다.

NOTE: 지도의 범례(legend)에서도 이를 확인하려면, parksmap을 0으로 스케일 다운한 후 다시 1로 스케일 업하여 앱이 캐시를 새로고침하도록 강제해야 합니다.

TIP: 실습이 끝난 뒤에는 GitHub 저장소의 **Settings → Webhooks**에서 Webhook을 삭제하거나, fork한 저장소 자체를 삭제해도 됩니다.

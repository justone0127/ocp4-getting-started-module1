[#project]
== Project란?

Project는 배포를 구성하고 관리하는 데 도움을 주는 OpenShift의 핵심 개념입니다. OpenShift Project를 사용하면 한 그룹의 사용자(또는 개인 사용자)가 다른 그룹과 분리된 상태로 자신의 콘텐츠를 구성하고 관리할 수 있습니다. 각 Project는 고유한 리소스, 정책(누가 어떤 작업을 수행할 수 있는지 정의), 제약 조건(리소스에 대한 쿼터 및 제한 등)을 가집니다.

Project는 여러분(또는 여러분의 팀)이 작업에 사용하는 모든 애플리케이션 서비스와 엔드포인트를 감싸는 "래퍼(wrapper)"라고 생각하면 됩니다. 내부적으로 OpenShift Project는 Kubernetes 네임스페이스(namespace) 위에 구축되지만, Project 추상화는 관리자에게 향상된 역할 기반 접근 제어(RBAC) 같은 추가 기능을 제공합니다.

Developer Sandbox는 바로 이 Project 기능을 이용해 하나의 클러스터를 여러 사용자가 안전하게 나눠 쓰도록 만든 환경입니다. Sandbox에 가입하면 **``{ocp4_starter_project}``** 형식의 Project가 여러분을 위해 하나 자동으로 생성되어 있습니다. 예를 들어 사용자 이름이 ``jdoe``라면 Project 이름은 ``jdoe-dev``입니다. 여러분이 만드는 모든 리소스는 이 Project 안에만 존재하며, 다른 사용자의 Project에서는 보이지 않습니다.

NOTE: Sandbox에서는 새 Project를 추가로 만들 수 없습니다(``oc new-project`` 명령이 거부됩니다). 이 워크샵의 모든 실습은 자동으로 만들어진 ``{ocp4_starter_project}`` Project 하나에서 진행합니다.

IMPORTANT: 이 가이드에서 ``<사용자명>``, ``<샌드박스-클러스터-도메인>``처럼 꺾쇠괄호(``< >``)로 표시된 부분은 **여러분의 실제 값으로 바꿔 읽어야 하는 자리 표시자**입니다. 복사해서 바로 실행하는 명령어는 가능한 한 이런 값이 필요 없도록 작성되어 있습니다.

=== 토폴로지 뷰

Project 내의 애플리케이션과 그 구성 요소를 시각적으로 표현해 주는 토폴로지 화면을 살펴보세요.

왼쪽 메뉴에서 **워크로드(Workloads)** 로 이동한 후 **토폴로지(Topology)** 를 선택합니다. 화면 위쪽의 **Project** 드롭다운에서 ``{ocp4_starter_project}``가 선택되어 있는지 확인합니다.

[.bordershadow]
image::openshift-console-topology.png[애플리케이션 구성 요소를 시각적으로 보여주는 토폴로지 화면,link=self,window=blank]

아직 애플리케이션을 배포하지 않았기 때문에 현재는 애플리케이션 구성 요소가 거의 보이지 않습니다(웹 터미널을 열었다면 웹 터미널용 구성 요소가 보일 수 있지만 무시해도 됩니다). 워크샵을 진행하면서 이 **토폴로지** 화면에서 애플리케이션의 구성 요소를 시각화하고 상호작용할 수 있게 됩니다.

[#project_cli]
== 실습: 명령줄로 Project 확인하기

OpenShift CLI를 사용해서도 Project와 상호작용할 수 있습니다. 웹 터미널에서 내가 접근할 수 있는 Project 목록을 확인합니다:

[source,bash,role="copypaste"]
----
oc projects
----

다음과 유사한 출력이 표시됩니다:

[.console-output]
[source,subs="attributes"]
----
You have one project on this server: "{ocp4_starter_project}".

Using project "{ocp4_starter_project}" on server "{ocp4_starter_api_url}".
----

현재 어떤 Project에서 작업하고 있는지만 간단히 확인하려면 다음 명령을 사용합니다:

[source,bash,role="copypaste"]
----
oc project -q
----

[.console-output]
[source,subs="attributes"]
----
{ocp4_starter_project}
----

별도로 지정하지 않는 한, 이후의 모든 ``oc`` 명령은 이 Project 범위 내에서 동작합니다. 만약 다른 Project가 선택되어 있다면 ``oc project <사용자명>-dev`` 명령으로 전환합니다.

[#sandbox_limits]
== 배경 지식: Sandbox Project의 제약 사항

Sandbox는 여러 사용자가 함께 쓰는 공유 클러스터이기 때문에, 여러분의 Project에는 몇 가지 제약이 미리 걸려 있습니다. 실습 도중 당황하지 않도록 미리 알아 두세요.

[cols="1,3",options="header"]
|===
|항목 |내용

|권한
|자신의 Project 안에서만 리소스를 만들고 수정할 수 있습니다. Node처럼 클러스터 전체 범위의 리소스는 조회하거나 변경할 수 없습니다.

|리소스 쿼터
|CPU, 메모리, 스토리지 사용량의 상한이 미리 정해져 있습니다. 실습 중 Pod를 크게 늘렸다면 반드시 다시 줄여 주세요.

|자동 유휴(Idling)
|일정 시간 이상 실행된 워크로드는 자동으로 0개로 스케일 다운될 수 있습니다. 워크샵을 이어서 진행할 때 Pod가 보이지 않으면 ``oc scale --replicas=1 deployment/<이름>``으로 다시 늘려 주세요.
|===

이제 Project에 익숙해졌으니, 이 Project에 애플리케이션 배포를 시작할 준비가 되었습니다!
